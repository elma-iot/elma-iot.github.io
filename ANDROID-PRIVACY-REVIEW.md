# Android privacy findings and Play Data Safety worksheet

Updated 10 September 2026. Android 1.0.0 / version code 1, `com.elma.iot.flasher`, source revision recorded in the Android testing-release report. The Android implementation was updated separately; no Android source or credentials are copied into this public website repository.

| Accounts | No ELMA account creation, login, email/password backend or social login. Device HTTP credentials and MQTT login authenticate to those user-selected destinations. Billing can use an existing Google Play account. |
| AdMob/UMP | Mobile Ads 25.4.0 and UMP 4.0.0 included. Gradle hard-codes productionAdsEnabled=false, yielding LIVE_MONETIZATION=false. Merged manifest retains MobileAdsInitProvider and advertising permissions. Source does not establish zero SDK background traffic. |

| Analytics/crashes | No separate Firebase Analytics, Crashlytics or Sentry integration. Paho logging is discarded; WebView console messages are suppressed. Provider SDK diagnostics are a separate issue and must not be ruled out by this finding. |
| IDs | Random temporary MQTT client ID; USB numeric device/vendor/product IDs and chip/flash details; configured ESP identity and device status; OTA random session ID. No direct IMEI, Android ID or phone advertising-ID read found in app-owned code. Google SDKs include advertising/app-set ID support. |
| Local compilation | LocalFirmwareCompiler runs bundled QEMU/GCC and SDK inputs in private Android storage. No PC compiler connection or cloud compilation API. Compiler caches, logs and completed firmware stay local; Save Firmware uses ACTION_CREATE_DOCUMENT. Legacy paired-PC credentials are removed on startup. |
| ESP/OTA | User-entered HTTP/HTTPS device URL, direct USB serial flashing/provisioning, and explicit-host OTA calls. HTTP Basic credentials optional for OTA. User-initiated LAN discovery probes the active IPv4 subnet and an optional entered IP using /api/status and /api/firmware/upload/status. Only compatible responses are listed. No discovery results are uploaded to ELMA servers. USB enumeration and Wi-Fi SSID scanning are distinct. Native phone MQTT test is connect/disconnect only; discovery publishing is delegated to the device. |
| MQTT | Paho 1.2.5 sends username/password to user-chosen broker; temporary client ID; in-memory persistence/clean session. Port 8883 or explicit tls option uses TLS with hostname verification, otherwise TCP. |
| Radio directory | Packaged app.js calls country-list loading during startup. Radio Browser receives HTTPS requests to all.api.radio-browser.info/json/countries and, when chosen/restored, /stations/bycountry/{country}. Receives IP/HTTP metadata and country preference. No GPS inference code in ELMA. Not an entirely offline app. |
| Artwork / device web pages | Shared source and packaged bundle contain Apple iTunes search for title/artist/album/filename during a device-storage media preview, plus artwork requests. Android Designer hides storage views and lacks a live device filesystem, so this is not a startup artwork upload. Device mode loads pages from the chosen device, whose behavior depends on firmware. Do not label the dormant packaged function as unconditional Android collection. |
| Browser CDN references | Shared browser USB flasher contains UNPKG/jsDelivr dynamic imports behind Web Serial support. Android Build uses bundled esptool-js; packaged page CSP only permits same-origin scripts. Do not declare automatic CDN downloads from merely finding strings. |
| ELMA servers | No central ELMA telemetry, analytics, account or cloud configuration endpoint found. User-selected broker/device endpoints and third-party services still transmit data off the phone. |
| Local storage | MainActivity preferences store full config and device URL; legacy elma-build pairing credentials are removed on startup; compiler inputs, logs and artifacts remain in private files; elma-purchase stores verified receipt/signature. WebView local/session storage holds preferences, radio selections and applicable caches. No app-layer encryption for preferences. Backup disabled and extraction rules exclude cloud/device transfer. |

| Compiler runtime | Bundled Android-native QEMU and shared dependencies plus guest GCC/glibc and Arduino ESP32 SDK. Used for local source compilation; no compiler telemetry or upload endpoint configured in the app. |
| Other libraries | usb-serial-for-android 3.10.0/esptool-js communicate with selected hardware; fflate/@noble/hashes process archives/checksums. No added developer telemetry endpoint found. |

## Current source versus intended production

The reviewed build now compiles locally and bundles its compiler and SDK for offline operation. `productionAdsEnabled=false` forces `LIVE_MONETIZATION=false` even if environment IDs are supplied. Ad requests and checkout are not active. `elma_remove_ads` is defined in code; product existence, pricing and activation in Play Console were not verified. No dedicated support address was found in the listing/configuration. The owner explicitly confirmed `elik745i@gmail.com` as the support email; retain it.

The policy now describes enabled production features conditionally, with a dated checked-build statement. The package ID remains unchanged. The signed testing release keeps production ads and checkout disabled; production monetization still requires separate configuration.

Wi-Fi: targetSdk 36, minSdk 26; ACCESS_FINE_LOCATION and ACCESS_COARSE_LOCATION requested together, fine grant required; ACCESS_WIFI_STATE and CHANGE_WIFI_STATE declared. No maxSdkVersion truncates those location declarations. API 28+ checks Location services; startScan/getScanResults are used. No NEARBY_WIFI_DEVICES, background location, Bluetooth/BLE or Nearby SDK. Android 13's nearby Wi-Fi permission does not replace fine location for these scanning APIs ([Android reference](https://developer.android.com/develop/connectivity/wifi/wifi-permissions)).

Yes/No entries below apply to the named flow and condition, not all SDKs combined. “Shared: Yes*” conservatively records an external recipient; use a Play sharing exception only after confirming its conditions. User-owned ESP transfers are shown separately from third parties. Conditional production rows must not be submitted as evidence of current active ads. Provider background processing that source cannot establish is explicitly unresolved, rather than assigned a fabricated No.

The checked app has no central ELMA collection server, but this is not equivalent to “no data collected.” Radio Browser receives IP; whether it derives location is unknown from source, so do not automatically label country preferences as physical location. Background SDK traffic, recipient retention, consent-specific optionality and applicable sharing exceptions require confirmation for the signed release. Crash-log collection specifically is not established by the app source; do not silently equate all diagnostics with crash logs.

For final form mapping: configuration content may map to other user-generated content/files, account names to user IDs, network/device identifiers to device or other IDs, and country/track queries to app activity/search history. Choose based on transmitted fields, not permission names. Local Wi-Fi scanning alone does not support a precise-location collection declaration. Do not mark remote processing as ephemeral without verifying recipient retention.

Sources: [Google Data Safety definitions and exceptions](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en), [Mobile Ads 25.4.0 disclosure](https://developers.google.com/admob/android/privacy/play-data-disclosure), [UMP](https://developers.google.com/admob/android/privacy). The SDK disclosure supplies the production ad categories; the Android code supplies gating and feature flows. No claim is made that the final Console form or provider configuration was inspected.

Support email requests concern data sent to the developer.
- Enable the production flag in a separately authorized Android change, supply valid production ELMA_ADMOB_APP_ID/ELMA_ADMOB_BANNER_ID and ELMA_PLAY_PUBLIC_KEY. Environment values alone cannot override the hard-coded false flag. Do not change com.elma.iot.flasher.

Configure AdMob/UMP messages and consent behavior, then verify purchase acknowledgement/restoration, ad-free ownership and consent scenarios on a signed Play test-track build.

- Supply private upload signing configuration, validate the final AAB and actual provider network processing; reconcile the matrix with all active Play versions and the final SDK configuration.
- Update Android's bundled privacy text and its Play listing policy URL in a separate Android change; existing in-app copy omits details now covered online. Keep the policy's dated source note as historical context or update it after verifying activation.
- Current `elik745i@gmail.com` is confirmed in listing.json and app privacy content. No dedicated address is confirmed; create one later, then update website/app/Console together.
